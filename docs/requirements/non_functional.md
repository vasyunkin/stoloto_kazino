# Нефункциональные требования (NFR)

Измеримые критерии для демо-стенда и целевого развёртывания «Воздушный Шар». Метрики согласованы с текущей реализацией ([PRESENTATION.md](../../PRESENTATION.md), код).

## Производительность

| ID | Требование | Метрика / критерий |
|----|------------|-------------------|
| NFR-P01 | Обновление состояния полёта в UI | Тики сервера **≤ 200 мс**; клиент fallback poll **200 мс** при недоступности WS |
| NFR-P02 | Время активации cashout | Ответ API cashout **< 500 мс** (p95) на локальном Docker при одном активном раунде |
| NFR-P03 | Старт раунда | `POST /start` включает lock кошелька и запись в БД **< 1 с** (p95) на демо-стенде |
| NFR-P04 | Первый экран игры | Hub без блокировки: сцена полёта подгружается lazy (Pixi не в первом бандле) |

## Доступность и устойчивость

| ID | Требование | Метрика / критерий |
|----|------------|-------------------|
| NFR-A01 | Health-check | `GET /actuator/health` → UP при работающих Postgres и API |
| NFR-A02 | Деградация транспорта | При сбое WebSocket ≤ **1,5 с** клиент переходит на REST poll без потери раунда |
| NFR-A03 | Рестарт backend | Все FLYING → VOID + **CREDIT_REFUND**; игрок видит исход «раунд отменён» |
| NFR-A04 | Целевая доступность (prod-цель) | **99,5%** monthly для API (вне scope учебного демо; задел в монолите + Postgres) |

## Безопасность

| ID | Требование | Метрика / критерий |
|----|------------|-------------------|
| NFR-S01 | Авторитет сервера | Клиент **не** вычисляет crash point и не принимает решение о крахе |
| NFR-S02 | Игровые операции | Cashout/start только для владельца `X-Player-Id`, совпадающего с раундом |
| NFR-S03 | Админ API | `/api/admin/**` (кроме login/refresh) — JWT Bearer или legacy key (dual-mode) |
| NFR-S04 | Секреты конфига | `api-key`, `jwt-secret` **не** возвращаются в GET config |
| NFR-S05 | Rate limiting | **40** запросов / **10 с** на `POST /start` и `/cashout` (in-memory) |
| NFR-S06 | Пароли админа | BCrypt cost **10**; refresh-токены хранятся как hash, отзыв при logout |

## Масштабируемость

| ID | Требование | Метрика / критерий |
|----|------------|-------------------|
| NFR-SC01 | Текущая архитектура | **1** JVM: активные полёты в памяти; горизонталь — задел (Redis / shared session) |
| NFR-SC02 | База данных | PostgreSQL 16, pool Hikari **max 10** — достаточно для демо и сотен игроков на одном узле |
| NFR-SC03 | Конфиг | Hot reload без редеплоя; аудит снимков без ограничения числа записей в `config_snapshot` |
| NFR-SC04 | Целевой рост | Поддержка **≥ 1000** одновременных полётов — требует выноса session store (roadmap) |

## Удобство использования (UX)

| ID | Требование | Метрика / критерий |
|----|------------|-------------------|
| NFR-U01 | Вход без барьера | **0** шагов регистрации до первого полёта |
| NFR-U02 | Читаемость K | Альтиметр с приборным шрифтом; K(0)=1, cashout с **1.01×** |
| NFR-U03 | Мобильный экран | При ширине **< 400 px** — упрощённый полёт (`lowDetail`), фидбек краша сохраняется |
| NFR-U04 | Обратная связь | Звук cashout/crash/UI; mute в шапке |
| NFR-U05 | Понятность честности | Commit на полёте; verify после финиша одним запросом |

## Сопровождаемость и качество

| ID | Требование | Метрика / критерий |
|----|------------|-------------------|
| NFR-M01 | Миграции схемы | Flyway версионирование (V1–V4) |
| NFR-M02 | Тесты интеграции | JUnit + Testcontainers Postgres 16 в CI/`mvn verify` |
| NFR-M03 | API-контракт | OpenAPI (springdoc) + единый JSON ошибок `{ code, message, timestamp }` |
