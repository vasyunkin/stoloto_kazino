# Функциональные требования

Источник: целевой процесс To-Be ([docs/bpmn/to_be.puml](../bpmn/to_be.puml)), реализованный продукт «Воздушный Шар».

Формат: **ID** — формулировка — (роль).

## Игрок и кошелёк

| ID | Требование | Роль |
|----|------------|------|
| FR-01 | Система создаёт и узнаёт игрока по `external_id` без регистрации | Игрок |
| FR-02 | При первом обращении начисляется welcome-баланс (демо) | Игрок |
| FR-03 | Игрок может запросить баланс и количество зарядов бустера | Игрок |
| FR-04 | Игрок может пополнить демо-счёт, если `allowDeposit=true` в конфиге | Игрок |
| FR-05 | Все списания и начисления отражаются в append-only журнале `wallet_ledger` | Система |

## Раунд и геймплей

| ID | Требование | Роль |
|----|------------|------|
| FR-10 | Игрок выбирает тему шара (STANDARD / LUCKY) с разной экономикой (ставка, α, потолок) | Игрок |
| FR-11 | Игрок задаёт ставку в пределах баланса и минимума темы | Игрок |
| FR-12 | Игрок может включить бустер (−1 заряд) или стартовать без него | Игрок |
| FR-13 | Система списывает ставку и создаёт раунд со статусом FLYING | Система |
| FR-14 | Система вычисляет коэффициент K(t) только на сервере | Система |
| FR-15 | Точка краша фиксируется на старте и не передаётся клиенту до конца раунда | Система |
| FR-16 | Игрок видит публичное состояние полёта (множитель, линия, очки, бустер) с частотой ~200 мс | Игрок |
| FR-17 | Игрок может выполнить cashout при K ≥ minCashoutMultiplier (1.01× по умолчанию) | Игрок |
| FR-18 | При достижении crash point система завершает раунд со статусом CRASHED | Система |
| FR-19 | При cashout система начисляет выигрыш и статус CASHED_OUT | Система |
| FR-20 | При VOID (например рестарт сервера) система возвращает ставку | Система |

## Бустеры и награды

| ID | Требование | Роль |
|----|------------|------|
| FR-30 | Система детерминированно решает спавн бустера и тир (×1.5 / ×2 / ×3) на старте раунда | Система |
| FR-31 | Активный бустер умножает коэффициент выплаты один раз на заданной линии | Система |
| FR-32 | Система начисляет очки за линии высоты и за активацию бустера (в т.ч. при крахе) | Система |
| FR-33 | После терминального раунда система выдаёт индекс фрагмента пазла (0–23) | Система |
| FR-34 | Клиент сохраняет собранные фрагменты альбома локально (24 слота) | Игрок |

## Социальный слой и прозрачность

| ID | Требование | Роль |
|----|------------|------|
| FR-40 | Система публикует рейтинг до N участников по сумме очков | Игрок |
| FR-41 | Система отдаёт ленту завершённых раундов без PF-секретов | Игрок |
| FR-42 | После завершения раунда игрок может verify: commit, seed, crash point, бустер | Игрок |

## Оператор и конфигурация

| ID | Требование | Роль |
|----|------------|------|
| FR-50 | Оператор входит в админ-панель (JWT) | Оператор |
| FR-51 | Оператор читает и изменяет runtime-конфиг (partial JSON merge) без рестарта JVM | Оператор |
| FR-52 | Невалидный конфиг отклоняется с кодом ошибки, процесс не падает | Система |
| FR-53 | Каждое применение конфига записывается в историю (`config_snapshot`) | Система |
| FR-54 | Изменение конфига не меняет параметры уже летящего раунда (снимок на start) | Система |

## Интерфейс

| ID | Требование | Роль |
|----|------------|------|
| FR-60 | Hub: выбор шара, доступ к альбому, рейтингу, правилам, депозиту | Игрок |
| FR-61 | Prefight: чипы ставки, выбор бустера, старт | Игрок |
| FR-62 | Flight: PixiJS-сцена, альтиметр, кнопка «Забрать» | Игрок |
| FR-63 | Result: исход, выигрыш/очки, фрагмент пазла, переход в альбом | Игрок |
