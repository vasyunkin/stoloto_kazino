# ADR 005: стиль интеграционного API

- Статус: принято
- Дата: 2026-11-23

## Контекст

AeroQuest предоставляет клиенту команды игрового процесса, историю раундов, кошелёк и административные операции. Клиенту важны понятный контракт, совместимость, проверяемая схема данных и документация для тестирования до готовности сервера. Для оперативных игровых тиков уже предусмотрен STOMP/WebSocket.

## Решение

Основной интеграционный интерфейс строится как REST API поверх HTTP и описывается OpenAPI 3.0.3. Ресурсы и действия используют JSON, стандартные методы HTTP и статусы. Доступ к административным операциям защищается JWT Bearer или настроенным API-ключом; игрок идентифицируется `X-Player-Id` либо JWT. Ошибки имеют формат RFC 9457.

STOMP/WebSocket остаётся каналом уведомлений о ходе раунда. Очередь сообщений (например, RabbitMQ или Kafka) рассматривается как направление развития для асинхронной событийной интеграции, когда появятся отдельные потребители событий и требования к доставке.

## Последствия

OpenAPI становится источником контракта, доступного Swagger UI и mock-серверу Prism. REST удобен для команд, истории, администрирования и тестирования обычными HTTP-клиентами. WebSocket и HTTP API требуют поддерживать два канала для real-time сценария. Очередь не вводится сейчас, поэтому система не получает её операционные расходы и гарантии доставки. Существующие публичные пути сохранены для совместимости; при развитии контракта новые операции следует проектировать в plural-ресурсном стиле.
