# Бизнес-процессы (As-Is / To-Be)

## As-Is: как задача решается без целевой ИС

Типичный crash-прототип или «ручной» стенд для демо/хакатона:

| Этап | Как делается сейчас | Узкое место |
|------|---------------------|-------------|
| Настройка баланса игры | Правки в коде или Excel, пересборка/рестарт | Долго, риск ошибки, нет аудита |
| Идентификация игрока | Лист с demo-id или одна общая сессия | Нет персонального кошелька и истории |
| Старт раунда | Клиент считает множитель или «доверие к скрипту» | Нет доказуемой честности, споры с жюри |
| Полёт | Обновление UI локально, рассинхрон при лаге | Игрок не доверяет результату |
| Cashout / крах | Ручная сверка в логах или таблице | Потери времени оператора, двойные списания |
| Рейтинг | Google Sheets / ручной ввод очков | Не связан с раундами, легко подделать |
| Коллекция / retention | Не ведётся или в заметках | Нет причины вернуться после проигрыша |

**Потери времени:** каждое изменение α, house edge или бустера требует разработчика; проверка честности раунда — постфактум по логам; демо для комиссии собирается «на коленке».

## To-Be: процесс после внедрения ИС «Воздушный Шар»

1. **Игрок** открывает веб-приложение → автоматический `demo-id` → welcome-баланс и заряды бустера.
2. **Игрок** выбирает тему шара, ставку, бустер → **ИС** списывает ставку, фиксирует crash point и commit, ведёт полёт на сервере.
3. **ИС** транслирует состояние (WebSocket / REST) → **Игрок** нажимает «Забрать» или получает крах → начисление выигрыша / очков / индекса фрагмента пазла.
4. **ИС** сохраняет раунд и проводки в БД → рейтинг и лента обновляются автоматически; альбом на клиенте пополняется.
5. **Оператор** меняет live-config в админке → следующие раунды идут с новыми правилами без рестарта; история изменений в `config_snapshot`.

**Точки автоматизации:** кошелёк и ledger; расчёт K и краша; cashout; PF verify; рейтинг; аудит конфига; публичная история без секретов.

## Диаграммы

| Файл | Описание |
|------|----------|
| [as_is.puml](as_is.puml) | Текущий (ручной / устаревший) процесс |
| [to_be.puml](to_be.puml) | Целевой процесс с ролями и автоматизацией |

Экспорт в PNG (в репозитории: `tools/plantuml.jar` + Java):

```bash
./tools/render-diagrams.sh
```

Или только BPMN:

```bash
java -jar tools/plantuml.jar -tpng docs/bpmn/as_is.puml docs/bpmn/to_be.puml
```

PNG лежат рядом с `.puml` (`as_is.png`, `to_be.png`, …).
