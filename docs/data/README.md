# Модель данных

## ER-диаграмма

Исходник: [er_diagram.puml](er_diagram.puml) → экспорт: `plantuml docs/data/er_diagram.puml`

Схема в репозитории: `src/main/resources/db/migration/V1__init.sql` … `V4__admin_auth.sql`.

## Ключевые сущности

| Сущность | Назначение |
|----------|------------|
| **player** | Игрок (`external_id`), баланс, заряды бустера |
| **game_round** | Раунд crash: ставка, статус, PF-поля, очки, фрагмент пазла |
| **wallet_ledger** | Неизменяемый журнал движений по кошельку |
| **config_snapshot** | Аудит изменений игрового конфига |
| **admin_user** / **admin_refresh_token** | Оператор и refresh JWT |

## Нормализация (3НФ)

- **1НФ:** атомарные поля; проводки ledger — отдельная строка на операцию; JSON конфига в `config_snapshot.payload` — документ аудита, не дублирует столбцы раунда.
- **2НФ:** все неключевые атрибуты зависят от полного PK (`game_round.id`, `player.id`, …); в ledger нет составного ключа с частичными зависимостями.
- **3НФ:** нет транзитивных зависимостей между неключевыми полями (например, `balance` не выводится из `external_id`; `win_amount` хранится как факт терминала, не пересчитывается из других неключевых полей в той же строке).

**Сознательно вне БД:** состояние активного полёта (текущий K, тики) — in-memory; собранный альбом — `localStorage` клиента.
